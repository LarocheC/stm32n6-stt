5. BLANK-PLACEMENT SHIFT THAT CTC COLLAPSES AWAY, OR A REAL SUBSTITUTION?
------------------------------------------------------------------------------
  A disagreement is collapse-neutral if reverting it to the host ids leaves
  the device's collapsed id sequence unchanged -- CTC swallows it.
  A blank-placement shift moves a whole token run by a frame, so it appears
  as several ADJACENT disagreeing frames that are only collapse-neutral
  together -- reverting any one of them alone changes the output.  The unit
  of the question is therefore the region: a maximal run of adjacent
  disagreeing frames (gap tolerance 0).

6. VERDICT
------------------------------------------------------------------------------
  Device-vs-host WER is 4.13 % (bootstrap 95% [2.59 %, 5.86 %])
  over 847 host words in 64 utterances.  Against the reference,
  host 5.92 % vs device 5.81 %; the paired difference is -0.118 points
  (bootstrap 95% [-1.290, +1.144], p = 0.8966; sign test p = 0.4545).

  SUPPORTED by these numbers:
    - the paired 95 % CI contains 0: this corpus does not show the device to be worse than the host
    - the device reproduces the host transcript exactly on 42 of 64 utterances
    - 70.78 % of frame disagreements are collapsed away by CTC and never reach the transcript

  NOT supported by these numbers:
    - 'no difference' is NOT established -- the same data are consistent with the device being up to 1.29 WER points worse
    - 64 utterances / 847 words is a small sample: the bootstrap CI on the paired difference is 2.43 points wide, so any true difference smaller than that is invisible here
    - one corpus (LibriSpeech dev-clean, clean read speech, <= 7.69 s) and one decode (greedy CTC); nothing here speaks to noisy audio, other speakers, longer utterances, or a beam search
    - the frames come from host-computed features fed to the device: this isolates the NPU, and says nothing about the on-device front end
