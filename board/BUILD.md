# Gate 4 — build, sign, flash, read

The recipe for turning this repository plus the vendored ST package into a
running Gate 4 image. Until now it existed only as prose scattered across
[`GATE3.md`](GATE3.md), [`GATE4.md`](GATE4.md) rounds 8-17,
[`firmware/apply_vendor_mods.sh`](../firmware/apply_vendor_mods.sh) and
`firmware/vendor-mods/`. Every step below is either a command that was run on
this machine or a `file:line` citation.

Scope: firmware only. Producing `artifacts/model_c/` (the ONNX fold, the
`stedgeai` compile, the weight blob) is a separate step and is **not** covered
here — see [`compile/GATE2.md`](../compile/GATE2.md) for the compile invocation
and `model/fold_stride2.py` for the blocker-1 fold.

## 1. Prepare the vendored tree

```bash
bash firmware/apply_vendor_mods.sh
```

`vendor/` is gitignored, so this script is the record of what the project
changes in ST's package. It is idempotent and derives the repo root from its own
location (`firmware/apply_vendor_mods.sh:10`) — the idiom the `board/*.sh`
scripts now use too. Its six steps:

| # | what | why | citation |
|---|---|---|---|
| 1 | replace `Middlewares/ST/AI/{Inc,Lib,Misc,Npu,Reloc,SystemPerformance}` with ST Edge AI 4.0.1's, and rewrite `NetworkRuntime1200` → `1201` in the Makefile | our model is generated by 4.0.1, whose `ll_aton` is 1.1.3-275; the package ships 262 and `network.c` has a hard `#error` on the mismatch. Backs the original up to `Middlewares/ST/AI.v262bak` | `apply_vendor_mods.sh:20-29` |
| 2 | `ai_dpu.c` — accept `STAI_FORMAT_S8` outputs | the stock check demands float32 **or** rank 2. Citrinet's CTC head is int8 rank 3 (`{100,1025,1}`), so both conjuncts hold, the model is rejected into `Error_Handler()` → `__disable_irq(); while(1)`, and the board hangs silently | `apply_vendor_mods.sh:34-48` |
| 3 | `cpu_stats.c` — add an explicit `#include <assert.h>` | GCC 14 makes implicit-function-declaration an error; `assert.h` used to arrive transitively through the pre-4.0 AI headers | `apply_vendor_mods.sh:53-61` |
| 4 | Makefile — add an `EXTRA_CFLAGS` extension point | `OPT += …` inside the Makefile is silently discarded when `OPT` is set on the command line, which drops `-flax-vector-conversions` and breaks CMSIS-DSP. **Never override `OPT` from the command line; use `EXTRA_CFLAGS`** | `apply_vendor_mods.sh:67-76`, lands at `Projects/GS/Makefile:230` |
| 5 | linker — `_Min_Heap_Size` 64K → 32K | the canned tensor is 64,000 B of `.rodata`; the heap it reclaims is for the capture ring buffer, which the canned path never allocates | `apply_vendor_mods.sh:82-85` |
| 6 | install `artifacts/model_c/{network,stai_network}.{c,h}` over the built-in AED model, and `network_atonbuf.xSPI2.raw` → `network_data.bin` | this is the compiled Citrinet graph. Backs the AED files up to `*.aedbak` | `apply_vendor_mods.sh:88-100` |

**Step 6 will overwrite the only surviving copy of the folded model.** The
vendored tree currently holds:

```
Projects/X-CUBE-AI/models/network.c.citrinet  9,967,286 B  2026-08-16 00:21   pre-fold
artifacts/model_c/network.c                   9,967,286 B                     pre-fold
```

`network.c.citrinet` and `artifacts/model_c/network.c` are the **same file**
(md5 `6902a02612795a0015e6a657785cceb5`); the installed `network.c` is neither.
The installed one is the stride-2-folded build produced during Round 17, whose
compile workspace was in the scratchpad that has since been wiped. Running step 6
now replaces it with the un-folded Gate-2 model and **re-introduces blocker 1**
(`Conv2D_70`, `GATE4.md:780-869`). Copy it aside first:

```bash
cp vendor/STM32N6-GettingStarted-Audio/Projects/X-CUBE-AI/models/network.c \
   /somewhere/safe/network.folded.c
```

**The installed weight blob does not match the installed sources.**
`network_data.bin` is 553,121 B (2026-08-16 11:55), which is a *truncated*-graph
blob from the Round 10-12 experiments, sitting next to a 9.9 MB full-model
`network.c`. `artifacts/model_c/network_atonbuf.xSPI2.raw` is 10,200,817 B. The
tree as it stands cannot produce a correct image; the model must be regenerated
and reinstalled before the next board attempt.

## 2. The Gate 4 `audio_bm.c` patch

`apply_vendor_mods.sh:106-107` ends by saying the `gate4_canned()` path is
"applied separately — see `firmware/vendor-mods/audio_bm.gate4.c.patch`".

**That file is not a patch.** It is 80 lines, 2,594 bytes, contains no `---` /
`+++` / `@@` markers, and is a truncated verbatim copy of the *head* of the
modified `audio_bm.c`, stopping mid-`init_bm()` at `MPU_Config();`. It carries
exactly one of the modification's hunks (the `#ifdef GATE4_CANNED` include block)
and does not contain `gate4_canned()` at all. `patch(1)` and `git apply` both
reject it. **There was no automated way to apply this step.**

There is one now. The vendored tree is a git clone, so the real diff is
recoverable, and it has been written to
[`firmware/vendor-mods/gate4.patch`](../firmware/vendor-mods/gate4.patch):

```bash
# regenerate (from the repo root)
git -C vendor/STM32N6-GettingStarted-Audio diff -- \
    Projects/GS/Src/audio_bm.c Projects/GS/Inc/audio_bm.h \
    Projects/GS/Src/stm32n6xx_it.c Projects/GS/Inc/app_config.h

# apply to a pristine v2.3.0 checkout.  The patch path must be ABSOLUTE:
# `git -C` changes directory before resolving it, so a repo-relative path fails.
git -C vendor/STM32N6-GettingStarted-Audio apply "$(pwd)/firmware/vendor-mods/gate4.patch"
```

Verified with `git apply -R --check`: the patch reverse-applies cleanly against
the current tree, so it describes it byte for byte. It touches
`audio_bm.c` (+338/-8), `stm32n6xx_it.c` (+254/-208), `audio_bm.h` (+8) and
`app_config.h` (+4/-1).

Everything it adds is behind `GATE4_CANNED`, `GATE4_BEACON` or
`GATE4_EPOCH_TRACE`, so with no extra defines `make bm` still builds ST's stock
application. What it adds:

| region | file:line | what |
|---|---|---|
| includes | `audio_bm.c:38-48` | `canned_features.h`, `mcu_cache.h`, `stai_network.h` under `GATE4_CANNED`; the `ll_aton` / `stai_aton_common.h` headers under `GATE4_BEACON` |
| context | `audio_bm.c:87-92` | replaces `AudioBM_proc_t audio_proc_ctx` with a bare `AIProcCtx_t g4_aictx`; with `audio_bm.h:51-60` shrinking `proc_buff`/`audio_out` to `[1]`, this drops ~269 KB of `.bss` the canned path never touches |
| `beacon()` | `audio_bm.c:120-125` | one character straight into `USART1->TDR`, waiting on `USART_ISR_TC`. No printf, no newlib, no heap — the instrument that proved the board was alive in Round 8 |
| epoch trace | `audio_bm.c:158-231` | per-epoch callback, §6 |
| boot markers | `audio_bm.c:270-323` | `UART_Config()` brought forward, then `HAL_Delay(12000)`, then `BEACON('1'…'9','D')` after each init step |
| `gate4_canned()` | `audio_bm.c:344-452` | feeds `kCannedFeatures` to the NPU, invokes, argmaxes each frame against `kExpectedTokens`, prints `# GATE4 PASS` / `FAIL`, repeats every 3 s |
| entry | `audio_bm.c:457-459` | `exec_bm()` calls `gate4_canned()` instead of the audio loop |
| IRQ reporter | `stm32n6xx_it.c:40-54` | under `GATE4_BEACON`, replaces ST's ~190 `while(1){}` handler traps with one that streams `IPSR`. Round 8 used it to prove no unexpected interrupt fires |

The headers it includes live in this repo, not the vendor tree, which is why the
build needs `-I$R/firmware/inc` (§3).

## 3. Build

From `vendor/STM32N6-GettingStarted-Audio/Projects/GS`:

```bash
export PATH=/home/claroche/STMicroelectronics/STM32Cube/STM32CubeProgrammer/bin:$PATH
cd vendor/STM32N6-GettingStarted-Audio/Projects/GS

make bm -j8 \
  GCC_PATH=/home/claroche/opt/st/stm32cubeclt_1.21.0/GNU-tools-for-STM32/bin \
  EXTRA_CFLAGS="-DGATE4_CANNED -I$(cd ../../../.. && pwd)/firmware/inc"
```

The Gate 5 builds additionally compile two sources out of this repository, which
is what `EXTRA_SOURCES` is for (a bare `-I` is not enough — see the Makefile hunk
in §2). The live-microphone image, which is the superset:

```bash
R=$(cd ../../../.. && pwd)
make bm -j8 \
  GCC_PATH=/home/claroche/opt/st/stm32cubeclt_1.21.0/GNU-tools-for-STM32/bin \
  EXTRA_SOURCES="$R/firmware/src/citrinet_fe.c $R/firmware/src/citrinet_ctc.c" \
  EXTRA_CFLAGS="-DGATE4_CANNED -DGATE5_WAV -DGATE5_MIC -DCITRINET_FE_USE_CMSIS=1 -I$R/firmware/inc"
```

`GATE4_CANNED` stays on in every Gate 5 build. It is what replaces
`AudioBM_proc_t audio_proc_ctx` with a bare `AIProcCtx_t`, and without it the
image carries ST's two `pCplxSpectrum[(NFFT/2+1)*2*COL]` arrays at 822,400 B
each and does not link at COL 800 (`firmware/AUDIO-INPUT.md` §7 correction 5).

This is the command `apply_vendor_mods.sh:103-105` prints on completion.
Output: `BuildGCC/BM/GS_Audio_N6.{elf,bin}` (`bm.mk:32`, `bm.mk:26-27`).

`make bm` is the bare-metal target. `CPU_STATS` is only compiled
`#ifdef APP_BARE_METAL`, and the utterance-based design has no concurrency to
schedule, so the `freertos` and `_lp` variants are not used
(`firmware/WORKLIST.md:100-121`).

### `EXTRA_CFLAGS`, and why not `OPT`

`OPT` accumulates the real compile flags across `Projects/GS/Makefile:5` and
`:225-227`. Setting `OPT=` on the command line makes make **discard every
`OPT +=` in the file**, including `-flax-vector-conversions`, which breaks
CMSIS-DSP. Step 4 of `apply_vendor_mods.sh` appends
`OPT += $(EXTRA_CFLAGS)` at `Projects/GS/Makefile:230` so there is a safe place
to add defines. Use it.

### The defines

| define | turns on | cost |
|---|---|---|
| `-DGATE4_CANNED` | the whole canned-feature harness: `gate4_canned()` replaces the audio loop, `AudioBM_proc_t` shrinks, `canned_features.h` is pulled in. **Required for a Gate 4 run.** | 64,000 B of `.rodata` for the input tensor; saves ~269 KB of `.bss` |
| `-DGATE4_BEACON` | `beacon()`/`BEACON()`, `UART_Config()` moved ahead of `MPU_Config()`, the 12 s post-UART delay, and the `stm32n6xx_it.c` `IPSR` reporter. Use it when the board says nothing and you need to know how far it got. | the 12 s delay on every boot |
| `-DGATE4_EPOCH_TRACE` | the per-epoch callback (§6). Requires `GATE4_BEACON` — it is nested inside it (`audio_bm.c:158` sits within the `#ifdef GATE4_BEACON` opened at `:109`) | **~14 ms per traced epoch**; see §7 |
| `-DGATE4_EPOCH_FROM=<n>` | window the trace: silent below epoch *n*, every epoch at or above it. Default 280 (`audio_bm.c:188-190`) | — |
| `-DGATE4_RISAF` | calls `RISAF_Config()`, which ST define and never call so `--gc-sections` drops it. Opens the RISAF firewall for SRAM1/2, the NPU master ports, SRAM3-6, FLEXMEM and OCTOSPI2 (`audio_bm.c:287-302`) | Round 8 tested it: **no change**. Not needed |
| `-DGATE4_XSPI_PREFETCH` | leaves XSPI2 automatic prefetch enabled instead of applying ST's undocumented "Hotfix for xspi: no prefetch" (`audio_bm.c:1164-1175`) | Round 13 proposed it against a throughput problem Round 14 showed did not exist. Not needed |
| `-DGATE4_CORPUS` | `gate4_corpus()` — the 64-utterance **feature** corpus at `0x71000000`, host-computed features straight to the NPU. This is what Round 20 scored | needs the corpus blob flashed |
| `-DGATE5_WAV` | `gate5_wav()` — the 16-utterance **waveform** blob at `0x72000000` through `citrinet_fe.c` on the M55 and then the NPU. PCM buffer in AXISRAM3 (`0x34200000`), front-end scratch in AXISRAM4 (`0x34270000`), neither of which the mpool or the linker script claims. Needs `EXTRA_SOURCES` | 256,000 B in each of two otherwise-unused banks; needs the waveform blob flashed |
| `-DGATE5_MIC` | `gate5_mic()` — the on-board **microphone**, MDF1 filter 0, 8 s per utterance, straight into the same AXISRAM3 buffer. Prints level (peak/RMS in dBFS, clipped-sample count), guard occupancy, the feature hash and 80 per-mel-row hashes, the argmax ids and the decoded text, twice per utterance: once on the captured audio and once after `citrinet_fe_peak_normalize()`. Then moves `MDF_GAIN` toward a −20 dBFS peak. If `GATE5_WAV` is also defined it runs **one** replay pass with row hashes first, as a parity check on the same image | the green LED is on while recording |
| `-DUSE_EXT_SRAM` | initialises the APS256 PSRAM and memory-maps `0x90000000` | **Only needed by the Round 11 `Slice` workaround**, which spilled 800 kB there. The Round 12 fold uses no PSRAM (`GATE4.md:963-975`), so leave it off. Without it, any access to `0x90000000` raises an imprecise bus error that escalates to HardFault (`GATE4.md:900-907`) |

A normal Gate 4 run is `-DGATE4_CANNED` alone. Add `-DGATE4_BEACON
-DGATE4_EPOCH_TRACE -DGATE4_EPOCH_FROM=340` only when hunting a stall.

### Size check

The app slot is `0x70100000` up to wherever the weights start. With the Citrinet
layout the weights are at `0x70400000`, giving 3 MB; ST's stock layout puts them
at `0x70180000`, giving 512 KB. `flash_and_verify.sh` enforces this (§5), but
the linker's own report is the earlier warning — RAM is the tighter constraint.
Gate 3's stock build used 57.62 % of the 1023 KB region (`GATE3.md:85-99`); the
Gate 4 canned build fits because of the `.bss` reduction in §2.

## 4. Sign — **`-align` is mandatory**

```bash
STM32_SigningTool_CLI -s -bin BuildGCC/BM/GS_Audio_N6.bin -nk -t ssbl -hv 2.3 \
                      -align -o BuildGCC/BM/GS_Audio_N6_sign.bin
```

> ### Do not use `make flash_bm`, and do not drop `-align`.
>
> **`bm.mk:39` signs without `-align`.** ST's Makefile predates the requirement;
> CubeProgrammer 2.21 made it mandatory and this machine runs 2.22.0
> (`GATE3.md:352-356`).
>
> Without it the payload does not begin at file offset `0x400`, and the signing
> tool writes the wrong entry point into the header at `+0x70`. Measured on the
> identical `.bin` (`GATE3.md:340-348`):
>
> | flags | header entry | verdict |
> |---|---|---|
> | ST's Makefile (`-s -bin -nk -t ssbl -hv 2.3`) | `0x34002F79` | in the middle of `.text` (`0x34000750`–`0x3401ACC8`) |
> | **`… -align`** | **`0x340167BD`** | equals `Reset_Handler` |
>
> The FSBL jumps into the interior of a function and the part dies instantly,
> before `UART_Config()` — a completely silent board with correct-looking flash.
> **That bug cost most of Gate 3.**

`-nk -t ssbl -hv 2.3` is always the same: unsigned, SSBL type, header v2.3, no
keys.

### The two-command gate, and run it every time

The word at `+0x70` of the signed image must equal `Reset_Handler | 1` from `nm`
(`GATE3.md:371-373`). Two commands, and it catches a silently-unbootable image
before it costs a boot-switch round trip:

```bash
NM=/home/claroche/opt/st/stm32cubeclt_1.21.0/GNU-tools-for-STM32/bin/arm-none-eabi-nm
test "$(xxd -e -g4 -s 0x70 -l 4 BuildGCC/BM/GS_Audio_N6_sign.bin | awk '{print $2}')" \
   = "$($NM BuildGCC/BM/GS_Audio_N6.elf | awk '/ Reset_Handler/{print $1}' \
        | sed 's/^0*//' | awk '{printf "%08x\n", strtonum("0x"$1)+1}')" \
  && echo "entry point OK"
```

`board/flash_and_verify.sh:50-62` runs exactly this before it writes anything, and
refuses to flash on a mismatch. Run against the image currently on disk it
reports header `340225f5` = `Reset_Handler|1` `340225f5` — that image was signed
correctly.

## 5. Flash

### Switch positions

The DK has two boot switches, and they are read only at reset — flipping one
under power changes nothing until the next reset (`GATE3.md:394-398`).

| position | mode | what it is for |
|---|---|---|
| both **RIGHT** | development | **program here.** Erase/write of external flash works only in this position |
| both **LEFT** | boot from flash | **run here.** Requires a power cycle, not a reset button (`GATE3.md:120-124`) |

### `mode=UR`, never `mode=HOTPLUG`

Measured access matrix (`GATE3.md:244-256`):

| operation | dev position | flash-boot position |
|---|---|---|
| `mode=HOTPLUG` connect | fails | fails |
| `mode=UR` connect | **works** | **works** |
| read external flash | **works** | **works** |
| erase / write external flash | **works** | fails |
| `ST-LINK_gdbserver` halt | fails | fails |

`mode=HOTPLUG` fails in *both* positions once the board has been booted from
flash, with `Unable to get core ID` / `No STM32 target found`. `mode=UR` connects
under reset, asserting NRST and catching the part early (`GATE3.md:399-403`).
This matters because ST's own `bm.mk:35` (`make flash_bm`) and ST's
`sign-and-flash-model.sh` both use `mode=HOTPLUG` — neither works on this board.

### The three regions

| region | address | source |
|---|---|---|
| FSBL | `0x70000000` | `FSBL/ai_fsbl.hex` (address is in the hex) |
| app (SSBL) | `0x70100000` | `BuildGCC/BM/GS_Audio_N6_sign.bin` |
| weights | `0x70400000` | `Projects/X-CUBE-AI/models/network_data.bin` |

`0x70400000` is the Citrinet base, set by `compile/stt_audio.mpool` — the only
difference from ST's `st_audio.mpool` is that pool's offset (`0x70180000` →
`0x70400000`) and size (63 → 60 MB). It gives the app a 3 MB slot instead of
512 KB.

### Flash it

```bash
board/flash_and_verify.sh  Projects/X-CUBE-AI/models/network_data.bin  0x70400000
```

Both switches **RIGHT**. The script (`board/flash_and_verify.sh`):

1. checks the signed image fits below the weights base and refuses if not —
   overflowing the slot silently overwrites the weight blob while every log
   still looks clean (`:42-48`);
2. runs the `-align` entry-point gate of §4 (`:54-62`);
3. writes the app with `mode=UR --extload` (`:65-66`), then the weights if given (`:68-72`);
4. **reads the app region back and byte-compares it** (`:75-87`). "File download
   complete" is the programmer's claim, not evidence, and this flash has held a
   714,560 B app in a 512 KB slot at least once.

Called with no arguments it defaults `SLOT_END` to ST's `0x70180000` (`:32`),
which is the right check for an AED control build and the wrong one for Citrinet.
Pass the weights address.

The FSBL only needs writing once per board, and is already in place here
(`GATE3.md:101-112`).

Then: **both switches LEFT, power-cycle** (unplug/replug — a reset is not
enough), and re-attach usbipd.

### If the probe wedges afterwards

`ST-LINK error (DEV_CONNECT_ERR)` immediately after a gdb session is a known
wedge with a software fix (`GATE3.md:375-390`):

```bash
usbipd detach --busid 1-1 && usbipd attach --wsl --busid 1-1
```

A *physical* replug is only required when the wedge follows a `validate` run.

## 6. Read the UART

```bash
/home/claroche/stm32n6-deployment-zoo/.venv/bin/python board/read_uart.py 60
```

`/dev/ttyACM0`, **14400 8N1** (`board/read_uart.py:22-24`). The baud is set at
`Projects/GS/Inc/app_config.h:58` and it is not a legacy default: 14400 is the
maximum the UART holds across the DVFS clock changes the app makes. `app_config.h:60-63`
records a measured attempt to raise it — **921600 breaks `UART_Config` at this
clock**, so both `#ifdef` branches remain 14400.

Nothing printed almost always means the board is still in development boot mode.
Both switches LEFT and power-cycle.

### A healthy boot

```
Ux20 1x20 2x20 3x20 4x20 5x20 6x20 7x20 8x20 9x20     <- only with -DGATE4_BEACON
System configuration (Bare Metal)
 SYSCLK clock : 600 MHz    HCLK clock : 400 MHz    CACHE conf. : $I/$D=(True,True)
 NPU clock    : 800 MHz    NIC clock  : 800 MHz
Dx20 Ex20
# gate4: canned features, mic bypassed
Lx20
AI_DPU: Activation are already allocated
Mx20
# ---- run 0 ----
# in=0x34350000 out=0x34350000 scale=8.297212 off=0
# fed 64000 B of 64000 B input
# invoking...
```

Marker meanings, in order: `U` `UART_Config`, `1` `MPU_Config`, `2`
`Int_Mem_Config`, `3` `Ext_Mem_Config`, `4` `NPU_Config`, `R` `RISAF_Config` (only
with `-DGATE4_RISAF`), `5` `IAC_Config`, `6`/`7` the cache enables, `8` sleep
clocks, `9` BSP init, `D` `displaySystemSetting()` returning — which also proves
the printf path works, since `D` goes through it. Then `E` entering
`gate4_canned`, `L` past the banner, `M` `AiDPULoadModel()` returned `DPU_OK`,
`I` entering `AiDPUProcess()`, `O` it returned (`audio_bm.c:280-323`, `:346-414`).

Input/output aliasing at the same address is expected, not a bug: the input is
dead by the time the CTC head writes, so the allocator reuses the buffer
(`GATE4.md:31-37`).

### The epoch trace format

With `-DGATE4_EPOCH_TRACE`, each epoch block emits one record. Written by
`audio_bm.c:204-211` on `PRE_START` and `audio_bm.c:221` on `POST_END`, all
fields **decimal**, zero-padded, no separators:

```
<352f019i393o098>07550957
 ^^^ ^^^ ^^^ ^^^ ^^^^^^^^
  |   |   |   |     `-- 8 digits: PMU cycles for this epoch (POST_END)
  |   |   |   `-------- 3 digits: out_streng_mask, output streaming engines
  |   |   `------------ 3 digits: in_streng_mask, input streaming engines
  |   `---------------- 3 digits: epoch-block flags
  `-------------------- 3 digits: epoch number, after '<' (PRE_START)
```

| field | example | decode |
|---|---|---|
| `<352` | 352 | epoch block 352 started |
| `f019` | 19 = `0x13` | `epoch_start \| epoch_end \| pure_hw` |
| `i393` | 393 = `0x189` | input streaming engines 0, 3, 7, 8 |
| `o098` | 98 = `0x62` | output streaming engines 1, 5, 6 |
| `>` | — | the epoch **completed** |
| `07550957` | 7,550,957 cycles | 12.58 ms at 600 MHz CPU |

**The last number printed without a following `>` is the epoch that hung**, and
its masks name the streaming engines it was waiting on. That is how Round 9
localised `Conv2D_70` and Round 15 localised `Conv2D_853`:

```
<351f019i008o032>07550957      ends
<352f019i393o098               starts, and that is the last byte the board sends
```

Below `GATE4_EPOCH_FROM` nothing is printed per epoch; instead every 64th epoch
emits a cumulative line (`audio_bm.c:223-227`):

```
E320t000106
 ^^^ ^^^^^^
  |     `-- 6 digits: cumulative NPU time in ms (g4_ep_tot / 600000, i.e. at 600 MHz)
  `-------- 3 digits: epoch number
```

`E320t000106` = 106 ms of NPU time accumulated through epoch 320.

Resolve an epoch to an operator by looking its index up in the compile
workspace's `network_c_info.json` / `network.csv`, exactly as Rounds 9-10 and
15-17 did.

## 7. Two instrumentation traps

`GATE4.md:1288-1301` records that **three** published conclusions in this gate
were overturned because the instrument, not the target, was what changed. Both
of the following produced wrong published numbers. Read them before trusting a
timing figure from this harness.

### `BEACON()` and the 2 s hold

`BEACON(c)` used to hold each marker for `20 x HAL_Delay(100)` = 2 s, so that a
one-shot boot marker could not be lost in the ~8 s usbipd re-attach gap.
`init_bm()` emits about sixteen of them, so **roughly 32 seconds elapsed before
the invoke was even entered** (`GATE4.md:1082-1090`). Round 13 divided wall-clock
by epoch count and published "the NPU is ~2000x too slow". It was not; Round 14
measured the epochs directly with the PMU and found them at ~1x the compiler's
estimate.

> **`BEACON()` must be shortened or disabled for any timed run.** Two seconds per
> marker is right for catching a boot that dies early and completely wrong for
> anything else. — `GATE4.md:1148-1150`

**Current state of the tree: already fixed.** `audio_bm.c:140` is now
`#define BEACON(c) beacon(c)` — one character, no hold — and the job of
outlasting the re-attach gap is done once by a single `HAL_Delay(12000)` after
`UART_Config()` (`audio_bm.c:273-280`). Do not reintroduce the per-marker hold.

### The epoch trace costs ~14 ms/epoch, and the print must come *first*

The trace emits ~20 characters per epoch and `beacon()` waits on
`USART_ISR_TC` for each, so at 14400 baud it adds **~14 ms per epoch** — about
9 s across a 628-epoch graph (`audio_bm.c:363-367`, `GATE4.md:1070-1071`). It is
opt-in for that reason. Useful for finding a stalled epoch, useless while
measuring one.

Worse, the order matters. The callback originally took the timestamp and *then*
printed:

```c
g4_ep_t0 = port_dwt_get_cycles();
if (...) { beacon('<'); g4_num(...); ... }   /* 18 chars INSIDE the window */
```

Eighteen characters at 14400 baud with a `TC` wait on each is 18 x 694 us =
**12.5 ms**, which is exactly the "uniform 12.6 ms per-epoch penalty, ±1 % across
seventeen epochs" that Round 15 published as a hardware timeout. The stability
that made it look like a fixed hardware wait was the stability of a fixed-length
UART write (`GATE4.md:1229-1247`).

**The print must come BEFORE the timestamp read.** `audio_bm.c:198-213` does this
now and carries the explanation in a comment. Re-measured that way, epochs
280-351 average 128,819 cycles = 0.215 ms, consistent with the compiler's
114.7 ms whole-graph estimate.

### The two rules

From `GATE4.md:1296-1300`, and they would have caught all three overturned
conclusions:

- **Never report a timing figure derived from wall-clock divided by a count.**
  Measure the thing itself.
- **When two measurements of the same quantity disagree, that is the finding.**
